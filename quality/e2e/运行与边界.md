# e2e 候选适配

状态：材料已准备；安装、MCP握手、实际target与run均Pending。完整接通主代理、委派、交接和工具适配后才集中验证。目录安装到MaaEnd工作树 `.qoder/maaend-private/quality/e2e`，不进入主仓package.json，不替换既有节点/native测试。

候选锁定 `e2e@0.21.2`、`@e2e-dev/web@0.15.2`（发行commit `393005aa6952eaef62886cd03c8d8060f8f05a4f`，Apache-2.0）；web依赖Playwright Core1.64.0。Node要求 `^22.22.3 || >=24.8.0`。官方Windows路线为WSL；先确认本机`wsl.exe --help`支持示例的发行版/--cd/--exec参数，不自动安装发行版或改变网络。

## 启用顺序

1. 审计当前仓库、候选构建与实际web目标，完成整体接通并取得执行/资源许可。MXU原生窗口或Tauri WebView没有受支持HTTP目标时，本适配不能运行；不得搭建假网页使它变绿。
2. 在该私有目录内审核package.json、候选npm包和transitive版本。用户允许下载后执行以下一次性命令；先生成锁、审核integrity与依赖，再下载。`--ignore-scripts`不代表下载内容已可信。

   ```bash
   npm install --package-lock-only --ignore-scripts
   npm ci --ignore-scripts
   ```

3. 审核实际安装文档及Chrome资格。需要下载浏览器时另行确认资源范围，再运行固定包的入口，不用`npx latest`：

   ```bash
   node node_modules/@e2e-dev/web/dist/bin.js install chromium
   ```

4. 设置真实target与已勘察的锚点。值由实际UI提供，不照抄示例占位：

   ```bash
   export E2E_TELEMETRY_DISABLED=1
   export E2E_UPDATE_CHECK_DISABLED=1
   export MAAEND_WEB_TARGET_URL='<reviewed-real-http-or-https-url>'
   export MAAEND_CANDIDATE_BUILD='<actual-artifact-digest>'
   export MAAEND_SUITE_DIGEST='<actual-suite-digest>'
   export MAAEND_EXPECTED_HEADING='<observed-exact-accessible-heading>'
   export MAAEND_PREVIEW_SELECTOR='<observed-video-selector>'
   ```

   URL不能含用户名/密码；本例还要求安全上下文的Web Crypto以便仅输出媒体源摘要。环境标签不能自行证明实际正在运行的进程就是该候选，接管人须把artifact→PID/target映射另记在私有证据中。未看到真实截图/DOM不能编造锚点。

5. 先用MCP勘察（常驻服务只在获准后启动，客户端结束负责关会话/进程），工具表以本次握手为准：

   ```bash
   node node_modules/e2e/dist/cli/bin.js mcp --config e2e.config.ts --target web --headed --max-sessions 1
   ```

   调用 `open_session` → `tools`/`tools {tool}` → `call {tool,args,session}` → `close_session`。MCP不执行测试、不写test result/cache。关闭会话并确认其浏览器、子进程和端口回收后，才运行集中验证：

   ```bash
   timeout --signal=TERM --kill-after=10s 120s node node_modules/e2e/dist/cli/bin.js run --config e2e.config.ts --target web --headed --no-cache
   ```

   记录退出码与原始stderr；非零不可隐藏。重试固定为0，worker固定为1。120秒外层超时是WSL/Linux示例，终止后仍核对完整进程树；不误杀用户浏览器。Qoder原生Windows可用`mcp.wsl.example.json`草稿，路径需人工映射，`disabled:true`保持到明确启用。

## 候选spec到底证明什么

`real-media.e2e.ts`只验证真实目标页面锚点可见、同一video源不断有新帧提交给合成器，输出源摘要以避免完整token URL进入结果。`getVideoPlaybackQuality().totalVideoFrames`包含丢帧，不能单独称为已解码/呈现帧；本例记录total、dropped、total-minus-dropped，并在浏览器支持时记录已弃用的可选corrupted字段。新帧判据来自有界`requestVideoFrameCallback`之`presentedFrames`与`presentationTime`递增；`mediaTime`也记录并在非零时检查前进，规范允许live/WebRTC的该值恒0。每次观察最多等待2秒，超时取消自己的callback，注册/回调/取消错误均显式处理，不留在页面异步抛出。

URL/blob URL路径绑定原`currentSrc`及原`srcObject`引用；WebRTC的`srcObject=MediaStream`不要求`currentSrc`非空。两次frame callback在同一个页面evaluate闭包内执行，绑定原video元素、同一stream对象、同一track对象集合。每次异步边界和回调重新核验引用、trackset与video track的live/enabled/unmuted状态，并用addtrack/removetrack、ended/mute及媒体重新加载事件使这次观察失效。哈希准备期间有变化也拒绝；报告只包含源/stream/video-track身份摘要、计数和活性，不返回URL或原始stream/track ID。event监听与待执行callback在finally中回收；暂时mute、重新协商或track替换都应作为本轮观察不稳定显式失败，再由真实生命周期适配处理，不能自动重试或继承旧源计数。

`presentedFrames`表示提交给合成器，仍不等于物理屏幕可见、游戏逻辑前进或像素内容确实变化。它也不证明输入隔离、云端松键、图像与帧计数原子绑定、完整任务或Native生命周期。页面没有heading/video、缺可取消的frame callback或renderer是canvas/img/worker时，当前spec应失败并标记适配缺口，不能替换成合成video或“截图接口成功”。真实登录、排队、游戏接管仍需SiteAdapter/FRD证据，不通过测试代码绕过。

计数语义来源：[Video frame callback规范](https://wicg.github.io/video-rvfc/)与[Media Playback Quality规范](https://w3c.github.io/media-playback-quality/)。

扩展时优先把一个真实短流程的可观察结束状态接入确定性断言；先明确真实target/owner与可调用能力，再写spec。Go/Cpp流程与MaaFramework不迁移到测试框架。`agent.act`可处理有语义目标的探索，`agent.assert`是模型判断；两者不替代精确`expect`和后端账本。默认配置没有独立模型，不会消费Qoder所选模型；若决定引入AI步骤，单独确认provider、模型、预算和费用，再按官方`e2e`技能配置。

## 会话与隐私

本配置新建独立浏览器，不附着已有云游戏。CDP普通attach会newContext；persistent模式初次使用已有页会先goto about:blank，后续attempt要求新浏览器。不要把现有已登录会话端口当无扰动读取口。多MCP/sidecar同target仍只准一个输入、导航、focus、resize和关闭owner。

关闭telemetry并不阻止应用/模型网络。官方MCP手动录屏不脱敏，本包默认video/trace关闭；截图/日志/网络证据仍须逐项脱敏。任何e2e配置/测试/自定义tool都以宿主权限执行，不是安全沙箱。
