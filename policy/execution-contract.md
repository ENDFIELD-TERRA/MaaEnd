# MaaEnd 私人执行约定

本文件只用于管理员的 Qoder CN 环境，不属于上游贡献规范。先读取真实全局和当前仓库规则，本文补充执行细节。不得将私人约定、安装回执和会话记录提交给上游。

工程顺序：先完成目标链路、联合接通与候选收敛，再集中正式测试和验收，随后优化性能。必要的诊断探针、解析/构建和仓库明确要求的检查仍应完成；不能把此顺序用作免测，也不能在长期未接通时用测试/优化替代实现。团队和提交/PR细节分别以 `team-workflow.md`、`commit-pr-contract.md` 为准。

## 开工与完成

- 把本次任务拆成原子需求，逐项写明对象、允许修改的模块和可观测结束条件。已有授权范围内完成所有本地准备和必要修复；实质决策才用交互工具等待裁决。
- 只读盘点分支、HEAD、remote、dirty、submodule/gitlink、锁文件、CI、最近提交和相关 Issue/PR 状态。`gh` 可用时优先；不可用用已授权 GitHub MCP。缺账号或网络时标记未核验，保留本地准备，不能虚构 Issue 编号或完成状态。
- 不自动 pull、merge、rebase 或切分支。需要最新信息先 fetch，比较范围；更新工作树是独立可审查动作。模型/测试集子仓保持主仓 gitlink，不追随 main。
- 先读脚本与锁文件再 install/build/test。不能因为 README/skill 提供命令就跳过供应链审计。不要执行 `curl | bash`。
- 目标违反仓库使命/Non-Goals，或要改动不该承担该职责的仓库时，先引用当前条款、解释影响和替代方案，使用交互工具取得明确确认。不能只问实现细节后直接接受目标。

## 增量实现与审查

- 遵守 MaaEnd `coding-standards.md` 的人类架构与 review 要求。先用契约、触发条件和小范围 diff 解释行为，让管理员理解。不能把“已提交代码”或“CI 通过”当完整 feature 验收。
- Pipeline 维持识别→操作→再识别；坐标以1280×720为准；无真实截图/ROI/模板/跳转证据不编写识别节点。延迟与重试按当前规范分析，失败不靠硬延迟/重试糊弄。
- Pipeline 管流程，Go 管难点；Cpp 优先复杂识别算法。当前回调句柄仅在本次回调内使用，controller/resource 每次回调仅获取一次，传给辅助函数，先判空。
- 维护注册、Custom Schema、任务入口和多语言的一致性；不主动新增 option description 或 Pipeline focus。修改 Markdown 前读 docs-guide。只修改任务相关文件，保护已有 dirty work。
- 用户全局命名约束作用于新贡献；Qoder平台要求的 `agents`、上游现有 `agent/` 路径、既有 skill 名等属于接口/既有符号，不为清除这些词而批量重命名。

## 测试选择

当前仓库 AGENTS 是 `pnpm check` / `pnpm test` 的裁决来源。发生更新重新读取，不把本表当永久规范。

| 本次改动 | 本地执行 | 证据与后续 |
| --- | --- | --- |
| 只改文档/私人配置 | 对应格式/配置解析与安装器安全验证；不跑两项全量套件 | docs-guide 要求 md check，不能凭 `format:md` 的0退出码判定通过（当前脚本带 `|| true`） |
| 包含 tests/**（用例、图片、hits/box） | 按当前规范先跑 pnpm test | 若同时改 assets/** 或 tools/schema/**，一并跑 pnpm check |
| 其他 Pipeline/Go/Cpp 改动 | 默认不主动跑两项全量套件；按规范做必要格式化/构建和针对性验证 | Go/Cpp 修改后的构建按当前指南；相应 CI 触发后跟进状态，提交前尚无 CI 就标记 Pending |
| 用户明确要求本地套件，或已授权具体诊断 | 在审计过的版本上运行所需命令 | 记录命令、退出码、原始失败及未覆盖边界 |

新增识别节点按 node-testing 与 maaend-test-image 的真实截图规范补必要用例，不编写复述实现的无效测试。格式化先检查命令范围，避免全仓脚本改动用户无关文件。失败必须修复、标记未通过或阻塞；不得悄悄略过 hook/lint/test。

## 委派与进程

- 独立任务才委派；每个子任务声明固定版本、输入/输出、模块、依赖、工具、完成判据和清理责任。共享协议、连续决策、简单修改由主线程持有；子代理不自行公开写入或替用户裁决。主线程收取证据并复核，结束前等待退出或主动停止。
- 所有命令设硬超时；交互决策等待采用宿主该次最大预算，不以超时推定批准。工程命令默认一次性，不启动 watch/无退出条件服务。确需常驻服务先取授权并说明停止方法。
- 启动构建、测试、浏览器等前盘点同类 PID、PPID、命令、cwd、启动时间。重型 TypeScript/构建/浏览器默认串行。不可终止责任不明进程。
- 同一目标失败两次，保存 stderr/退出码与复现命令后暂停该路径，诊断根因和替代方案；60秒无进展且无合理等待依据就诊断。超时/退出回收自己产生的完整进程树和端口，不以 MCP断连当浏览器已退出证据。
- 清理本次无后续用途临时文件；需保留常驻资源时在交接列出。

## 公开内容与 Git 风格

- 本地修改/修复连续完成；push、远端 Issue/PR/评论、部署发布和共享写入先把最终内容与目标准备好、逐项脱敏，再通过交互工具请求最终确认。未获确认保持私有草稿。读操作不需要此审批。
- 检查凭据、token、cookie、账号/UID、路径、内部代号、会话/工具日志和私人信息。截图、trace、网络包也需审查。不能把自动化检查通过当保密保证。
- 最近有效样例以实际 log 与 PR 为准：当前 MaaEnd 常用 `feat(Scope): 中文技术摘要`、`fix(Scope): 中文技术摘要`，亦有无scope；文档 `docs:`，skill/提示词 `ai:`。不要模仿机器人 release notes、自动格式化、cherry-pick脚注、模型署名。PR按问题、最终行为、必要验证写，关联正确Issue；完成整feature验收后才申请关闭，部分PR不能提前关闭主需求。
- 不主动改 README；不改写他人提交历史。历史重写只有用户要求且只允许 XSPR 作者 message/body，非XSPR内容树、作者、主题、正文均保留；本任务不执行历史重写。

## 浏览器能力与验收

- Playwright MCP 使用其实际 tools/list 和页面快照；Chrome DevTools 使用其实际schema与官方skill。CLI skill不是MCP工具。所有技能中的 `latest` 仅为上游示例，本环境使用固定已审核版本，不自动升级或照搬其他客户端字段。
- 默认两个MCP各自使用独立临时profile、可见Chrome窗口；不自动连接个人浏览器或扫描现有CDP端口。真实云游戏需批准专属持久profile与进程生命周期；同一个target只有一个输入/导航/focus/resize owner，另一端只在协调后观察。诊断工具不会取代生产sidecar输入循环。
- 先取得服务握手/工具表，再在无账号的受控页分别验证读取、点击/填充、截图、释放和回收。连接状态、页面控制、Windows输入隔离、媒体新鲜度、真实任务成功分别验收。
- `AGENTS.md`、人格与提示词提供行为约束，不是强制安全沙箱；权限来自当前主会话。不得以子代理权限配置承诺能收紧父会话的 auto/bypass/acceptEdits。未证明交互工具、权限闸和浏览器清理有效前只报 Pending。
